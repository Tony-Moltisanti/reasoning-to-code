# Lesson 3 — Valid Reasoning and Common Conditional Fallacies

## Modus ponens — valid

1. If P, then Q.
2. P is true.
3. Therefore Q is true.

Example: If payment succeeds, the appointment is confirmed. Payment succeeded. Therefore, the appointment is confirmed.

## Modus tollens — valid

1. If P, then Q.
2. Q is false.
3. Therefore P is false.

Example: If the system has received a valid authorisation, access is granted. Access was not granted. Under the stated rule, valid authorisation was not received.

## Affirming the consequent — invalid

1. If P, then Q.
2. Q is true.
3. Therefore P is true.

This is invalid because Q may have another cause.

Example: If payment succeeds, the appointment is confirmed. The appointment is confirmed. Therefore payment succeeded. That conclusion is not guaranteed.

## Denying the antecedent — invalid

1. If P, then Q.
2. P is false.
3. Therefore Q is false.

This is invalid because Q may still be true for another reason.

Example: If verified, a patient can access records. The patient is not verified. Therefore the patient cannot access records. Another authorised route may exist.

## Key lesson

A conditional tells us what follows when its condition is met. It does not automatically tell us that the outcome can happen only through that condition.
